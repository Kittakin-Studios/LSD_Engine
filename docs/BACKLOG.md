# Backlog

Every feature planned for LSD_Engine, placed in the milestone that builds it.
`[x]` done · `[~]` partly done (note says what's missing) · `[ ]` to do.
Sources: the engine's feature spec (see [ARCHITECTURE.md](ARCHITECTURE.md) and [ROADMAP.md](ROADMAP.md)), plus the public
feature sets of Unreal Engine 5 and Autodesk Stingray (ideas only, see `docs/CLEAN_ROOM.md`; our own names and formats).
Unreal names in brackets. **(S)** = idea taken from Stingray's public feature list.

Rule for placing things: a feature goes in the earliest milestone whose exit test needs it, or that
everything later depends on. Anything a small team does not need to ship a first game goes to v2 or Later.

## Milestone 7 — Gameplay languages (C, C++, JavaScript)

Gameplay so far is Lua and visual scripts. This milestone adds native code (C and C++, like Unreal's
C++ project modules) and JavaScript, all on one API, while UI stays HTML / CSS with its own `.js`.

Exit test: in one level, a door opened by a C++ behaviour and a pickup counted by a JavaScript script,
edited and reloaded while the editor runs, then packaged and run from another folder. **Passed (Nov 2026)**:
both edited during Play carried on from where they were (the door's height property and the pickup's
`self` kept), and the packaged game run from Build/<Project>/ logged both.

The shared core: every engine call scripts make already goes through `ScriptHost` (plain C function
pointers) and the reflection tables. Both become the C API, so every language sees the same calls.

## Performance (measured)

Measured in Release on D3D12 with `stat dump` and a stress level of 3000 objects over 300 m (sun shadows on):

- [x] Saving / snapshotting a level: 6469 ms -> 14 ms (Array::resize grew to the exact size, so every append copied the whole text)
- [x] Editor UI frame: 26 ms -> 1.5 ms (the Outliner's hierarchy scanned every object for every object; now child lists built once a frame, rows clipped to the visible ones)
- [x] Mesh / texture / material lookups: a hash index per cache instead of comparing every entry (every object, every pass); mesh cache reserved so pointers stay valid
- [x] Sun shadow casters culled per cascade (sides only, pancaking kept), spot / point tiles per face
- [x] `stat dump`: game / render / UI / GPU-wait times, draws, triangles, culled and the UI by panel (the GPU wait was counted as render before)
- [x] Automatic instancing: opaque Static Meshes with the same mesh, LOD and look draw as one instanced call (872 -> 9 draws in the stress level), shadow casters too (per cascade / tile), Instanced Static Mesh casters in one call; instanced normals use the cofactor matrix, so any scale batches
- [x] Each Static Mesh's world matrix and mesh worked out once a frame and shared by every pass: render CPU 3.3 -> 1.95 ms at 3000 objects
- [x] Navmesh reused between Plays while its inputs hash the same (Play start 191 -> 5 ms at 3000 objects)
- [x] GPU timings: timestamp queries in D3D12 and OpenGL (read a frame or two later, no stall), `stat dump` prints shadows / scene / post / UI (3000 objects: 1.3 ms of GPU on this PC; post is the largest part)
- [x] GPU-driven culling: Instanced Static Meshes and automatic instancing batches with 32+ copies are culled on the GPU (`r.GPUCulling`, on): a compute pass (engine/rhi/shaders/cull.hlsl, `rhi::CullConstants`) tests each copy's box against the view frustum (`rhi::frustum_planes` / `instance_visible`, the same test on the CPU for the tests), picks its LOD from its screen size (`rhi::instance_lod`, as pick_lod), tests it against a Hi-Z depth pyramid built from the main viewport's depth (`PostDraw::build_hiz`, the HIZ_PASS kernel; one frame late, so a copy coming out from behind a wall can show a frame late), packs the visible rows per LOD, and the draws run through indirect arguments per LOD and batch of 256 (D3D12 ExecuteIndirect, OpenGL glDrawElementsIndirect, Vulkan vkCmdDrawIndexedIndirect); shadow passes cull Instanced Static Mesh copies against the light's view on the GPU (D3D12, OpenGL; Vulkan on the CPU). Shortcut: ordinary objects take part only as automatic instancing batches, not through one GPU scene buffer
